## New contradictions introduced by the fixes (top 5)

1. **A set-once provenance column is written repeatedly (TDD-7 fix vs the state machine).** Plan 29 §6.1 l.122 makes `task_generations.implementation_commit` set-once. `E_RECORD_IMPLEMENTATION_COMMIT` runs on every accepted implementer result (state-machine T032 l.574, and l.1252), including GREEN retries and review-requested changes within one generation. `tdd-provenance-survives-retry` relies on that path. The trigger would reject the second write, so as specified every in-generation retry fails.
2. **R8 does a full-suite comparison but the RED head run is scoped (TDD-4 fix).** Plan 22 R8 l.227 says absent tests count as not passing in a "full-suite set comparison". 22-AC-25 expects absent-at-head to fail R8 at RED. Yet §14.1 step 4 l.193 still limits the RED head run to `redScope`. Every base-passing test outside the scope is "absent", so every scoped RED would be `red_invalid` (`preexisting_test_removed`).
3. **Revoke-on-receipt breaks the idempotent result replay (RA-4 fix vs RA-13 and plan 27).** Plan 26 §14.4 step 4 l.510 promises that "an identical replay returns 200" and then revokes the runner task token immediately. `task-token.schema.yaml` requires `revoked_at IS NULL`. A worker that lost the 202 and retries gets 401, and plan 27 l.100 defines no 401 handling. The result is lost unless log recovery applies. Plan 35 l.532 still says the token is revoked "at terminal state or cancel".
4. **An acceptance criterion contradicts the accepted residual (TDD-3 fix).** Plan 22 §14.4 l.243 says a test conditional on the `SC-STUB` marker is "exactly the behavior change G9 tolerates". 22-AC-24 (l.404), the fake `phase-conditional-test` (plan 21 l.295) and plan 28 l.319 nevertheless expect `tamper_detected` (`red_not_reproducible`) for that test. That AC and the fake cannot pass; only the commit-subject variant can.
5. **`QUEUE_TIMEOUT` is defined three ways (RA-7 fix).**
   - Plan 26 l.487 and l.560 use `queue.maxQueueAge`, which is not in its §9.1 config table.
   - Plan 29 l.328 and l.482 and state-machine l.1327 use `spec.retry.infrastructure.queueTimeout`, default 2 h.
   - Plan 51 l.247 gives a queue age of 6 h.
   - `SCRunnerQueueBacklog` (> 2 h, plan 26 l.669) fires at the same moment as the 2 h timeout.
   - Plan 29 l.482 and state-machine l.1327 say "the Job is not unsuspended while waiting", but plan 26 l.487 says a QUEUED execution "never has a Job".
