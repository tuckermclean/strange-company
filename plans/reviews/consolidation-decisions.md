## Post-PR adversarial review (PR #138), 2026-10-14

The external adversarial review is recorded in `plans/reviews/external-review-pr138.md`. The decisions below resolve its findings.

| ID | Finding | Decision | Files that must conform |
|---|---|---|---|
| CD-27 | X#1: Stage-0 verification was asserted in prose, not reproducible. | A committed, deterministic **Stage-0 validator** (`tools/stage0/validate.py`, pinned Python deps) performs every check `STATUS.md` claims and fails on any violation. `PLAN.md` is regenerated by `tools/stage0/genplan.py`, and the validator fails if the committed `PLAN.md` differs. GitHub Actions runs the validator on every PR (`.github/workflows/stage0-validate.yaml`). It is the interim trusted CI of ADR-0018 for Stage-0 artifacts. ADR-0021 records the Python exception to ADR-0002. `STATUS.md` cites validator output, not prose. | tools/, .github/, STATUS.md, PLAN.md |
| CD-28 | X#2: `perRequest.maxCostUsd` was not a maximum; plans admitted unbounded overrun. | **`maxCostUsd` is a hard ceiling.** The Gateway admits a request only if its **provable worst-case cost** ≤ `maxCostUsd` and fits every scope's headroom. The reservation equals that same worst case, so shared scopes cannot overshoot either. The worst case is computed as follows. **Input tokens:** the exact count from a pinned local tokenizer or the provider's count endpoint; otherwise the declared upper bound `inputTokensPerByteUpperBound × UTF-8 bytes + perMessageOverhead × messages + perRequestOverhead`. That defaults to 1 token per byte for byte-level BPE families and is verified per family by a fixture-corpus AC; content without a bound (e.g. images without a documented formula) is denied. **Output:** the enforced `max_tokens`, including reasoning; a model whose output cap does not bound reasoning is denied unless a separate enforced reasoning cap exists. **Cache writes** are priced at the highest applicable rate. If the provider-reported usage ever exceeds the computed bound, the Gateway records a `BOUND_VIOLATION` and alerts. That is treated as a provider or tokenizer anomaly, not as normal overrun; the ceiling holds by construction otherwise. No SPEC amendment is needed. The byte-ratio estimator is removed. | 31, 32, 33, 53, ADR-0450, budget-policy & model-routing contracts |
| CD-29 | X#3: plans reason against "latest at implementation time", so third-party drift could reopen architecture. | A **Stage-0 compatibility baseline** (`plans/compatibility-baseline.yaml`) records, per third-party component, the exact version or release line the plans were reasoned against, with the evidence date. Implementation pins **within the baseline line**: patch updates are free; a newer minor or major is an **explicit plan-amendment task** that updates the baseline, re-runs the affected plans' `(verify)` ACs, and is reviewed like any architecture change. Version "selection rules" in plans are superseded by the baseline (ADR-0022). | all plans with selection rules; master plan §6.3 |
| CD-30 | X#4: Runner admin API took `X-SC-Actor` from the caller, so a shared bearer could impersonate anyone. | **Identity comes from the credential, never from a header.** `X-SC-Actor` is removed. `SC-RUNNER-ADMIN` becomes **per-operator** admin credentials (key id → operator identity, issued and revoked by `sc-bootstrap access join|leave`), plus one **break-glass** credential whose actor is always `breakglass:runner-admin`. `X-SC-Reason` stays caller-supplied. Every audit row records the credential key id. | 26, 35, 15, 50, runner-api contract, ADR-0400 |
| CD-31 | X#5: seed→Flux rollback (N4) and fault cases (N5, N6) were proven only on the k3d substitute stack. | Cases **N4, N5 and N6** also run in the **lab-VM gate with real Longhorn, CNPG and Forgejo** (disposable, never the production node), as required ACs of GATE-P04/P06 or their lab equivalent (plan 05 lab substrate). | 19, 05, 52 |
| CD-32 | X#6: one RTO conflated "bytes readable" with "factory working". | Split every RTO into **data-availability RTO** (the data is readable or restorable by the operator) and **service-restoration RTO** (the service is serving its function again). SPEC §108's RTO column is interpreted as data-availability. Stage 0 adds service-restoration targets: Forgejo serving `main` and Flux reconciling ≤ **4 h**; Strange Company resumed (Runner dispatching after verify) ≤ **6 h** after start of a total-loss black start. Drills measure and report both. | 44, 45, 11, master plan §8, spec-issues |
| CD-33 | X#7: black start silently depends on GitHub's Git service, GHCR, release assets and Pages. | Define a **bootstrap capsule** in the recovery failure domain (S3 `recovery` bucket, Object Lock). It contains: the signed toolbox image archive; the k3s air-gap bundle; the seed-set and restore-path chart archives and images (Flux, cert-manager, CNPG + plugin, Longhorn, Traefik, cloudflared, Forgejo); the Ansible collections; and a repository bundle of `strange-company`. It is refreshed on every release or upgrade, digest-manifested and signed, and verified by a restore test. `./bootstrap recover --from-capsule` performs black start with GitHub fully unavailable. Implemented at **H04** (post-MVP hardening). Until then, a GitHub-wide outage during total loss is an accepted, recorded risk (SI-43 updated). | 45, 14, 43, 44, 02, 50, 23, dag.yaml |
| CD-34 | X#8: fresh-context reviews are not independent of the review corpus. | After the CD-27..33 fixes, run **blind** reviews of the most dangerous areas (security/admission, TDD enforcement, DR/black start, seed→Flux, budgets). They use a **different model** from the authoring model. Only Anthropic models are available in this environment, so true vendor-family diversity is not achieved; the external review supplies it. Reviewers must not read `plans/reviews/**` (except `consolidation-decisions.md`, which is binding design) before forming their findings. Their reports go to `plans/reviews/blind-*.md`, and their findings are fixed or explicitly dispositioned. | plans/reviews |
