## 2. Verdict

**FAIL.** The compute guardrails, the toolbox, the provider abstraction and destroy are solid, and most of the work is careful. Two of the six DoD items cannot be signed:

1. `./bootstrap --profile self-hosting-minimum` cannot reach `CONTROL TRANSFER COMPLETE` by itself (BOOT-1).
2. The resume rules as written re-run seed, forge-init and flux-bootstrap after the source switch. That is unsafe, and the most common resume case (a failed `verify`) fails deterministically (BOOT-2).

Both are fixable without architectural change.

## 4. Circular-dependency analysis

**DAG (`plans/dag.yaml`):**
- **F08 ↔ F09 (AC-level cycle).** GATE-F08 (50-AC-4/-5/-10/-11/-15) uses provider `fake`. The fake provider is plan 03's (F09), and F09 depends on F08. See BOOT-11.
- **F08 ↔ P01 (AC-level cycle).** `make e2e-bootstrap-fake` runs the real storage-apply, conformance, migrate, credentials and bundle steps (plans 06/14/35, P01), and P01 depends on F08. See BOOT-11.
- **F10 missing edges.** Its gate uses `./bootstrap configure` and the lab provider (F08, F09), but its only dependency is F03. See BOOT-11.
- **P12 → P11 → (human merge, tag, release, promotion merge).** This is not a graph cycle, but P12's gate depends on external human actions that one pipeline run cannot contain. See BOOT-1.
- Otherwise P01→…→P12 is acyclic and consistent with plan 50's phases. H01 depends only on P12, which is correct.

**Runtime and bootstrap ordering:**

| Ordering | Status |
|---|---|
| State bucket before OpenTofu | Resolved: encrypted local storage state, then migrate (ADR-0100). Conformance needs a credential minted later in plan 50's order, and the remote run-lock credential is undefined (BOOT-10). |

## 5. Proposed `plans/spec-issues.md` entries

1. **SPEC §130 vs the trusted supply chain (§37, P11).** "Functioning Strange Company without manual steps" cannot include an installation-owned signing key plus a first trusted release, because those need human-merged PRs. Proposed resolution: §130 is satisfied with upstream-signed release images. The operator's own release chain is a post-P12 milestone, or §130 explicitly lists "review and merge the generated trusted-keys PR" as an allowed operator action. (BOOT-1)
2. **SPEC §7/§130 prerequisites omit GitHub.** A GitHub repository with mirror, probe and read tokens is required by §6, §32 and §35. Rulesets on private repositories may need a paid GitHub plan or an organization (SI-20). The list should name it. (BOOT-13)
3. **SPEC §14 vs object storage.** "Paid infrastructure" is interpreted as compute only; buckets are created before the footprint confirmation. Record the interpretation, or require a storage confirmation (recommended). (BOOT-12)
4. **SPEC §15 "restricted credentials" vs `S3_CREDENTIAL_MODE=shared`** (the default for `generic`/`b2`). The in-cluster admin key can delete state history. Either forbid shared mode for `tofu-state`/`recovery` or record an explicit, reported exception. (BOOT-3)
5. **SPEC §15 for providers without OpenTofu** (`existing` with pre-created buckets). The state requirements are vacuous; record that V-33 and RT-5 are conditional. (BOOT-4)
