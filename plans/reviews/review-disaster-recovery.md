# Independent review — Disaster recovery and black start (SPEC §132 item 45)

**Reviewer:** independent fresh-context reviewer · **Date:** 2026-10-14 · **Brief:** `plans/reviews/review-brief.md`

## 1. Scope reviewed

Read completely: SPEC §0–§4, §15, §26, §29, §31–§32, §98, §107–§114, §117, §119, §125, §130, §132; `plans/45-recovery.md`, `44-backup.md`, `12-cnpg.md`, `13-longhorn.md`, `14-object-storage.md`, `06-opentofu-state.md`; the DR-relevant parts of `07-k3s.md` (§10, §15, §18, §20, ACs), `17-github-mirror.md` (§6, §10, §13–§20, §24–§25), `19-seed-handoff.md` (§8.4, §18.3, §20), `35-secrets.md` (§1–§11, §14–§25), `47-ha-expansion.md` (drills), `50-bootstrap-orchestrator.md` (CLI, §13 commit scope, §14.9 recover, V-checks); procedures `total-cluster-loss`, `github-black-start`, `recovery-drill`, `restore-cnpg`, `restore-longhorn`, `restore-forgejo`, `restore-authentik`, `restore-etcd`, `lost-node`, `lost-etcd-member`, `recover-opentofu-state`, `object-storage-outage`, `rotate-age-key`, `restore-test-failure` (plus spot reads of `cnpg-primary-loss`, `provider-outage`, `credential-compromise`, `rotate-secrets`, `sops-decryption-failure`, `safe-destruction`); contracts `recovery-record`, `recovery-bundle`, `restore-test-result`, `secret-classes.yaml` (object-storage instances, bundle flags); ADRs 0012, 0013, 0019, 0158, 0204, 0253, 0500, 0554; `plans/dag.yaml`; `plans/spec-issues.md`; `plans/reviews/consolidation-decisions.md`.

Method: I simulated, step by step, (A) black start from total loss with only GitHub + object storage + passphrase/offline key, then (B) loss of the object-storage provider, (C) loss of GitHub, (D) loss of the operator laptop, (E) loss of the cluster age key, (F) etcd corruption, (G) CNPG PITR to a past time. The findings below are where a simulation stopped, forked into undefined behavior, or produced a wrong result.

## 2. Verdict

**FAIL** (fixable). The architecture is sound and unusually thorough: generation-qualified CNPG archive paths, the Git-explainable recovery commit, fencing, mirror disablement until ref reconciliation, two-tier SOPS, a passphrase bundle with attestation, and an RPO/RTO table that names a mechanism and a measurement for every SPEC §108 row. But three defects make the specified paths unexecutable or unsafe. As written, black start can never reach `CONTROL TRANSFER COMPLETE (RECOVERY)` (DR-1). The quarterly D2 drill fences live production if implemented per plan 45 (DR-2). The CNPG replace/PITR procedure deadlocks for `sc-pg` and `woodpecker-pg` (DR-3). Each has a local fix. Once DR-1..DR-3 and the majors listed per DoD item are fixed, this area would be PASS WITH FIXES.

## 5. Items for `plans/spec-issues.md`

1. **SPEC §35 vs recovery (process gap, not a SPEC contradiction).** Recovery must not declare "control transfer complete" before the mirror works. Record the DR-1 resolution: two report stages in recovery.
2. **SPEC §108 (project repositories RPO ≤ 1 h).** Plan 44's > 2 GiB incremental rate limit is a weakening that must either be removed or listed (DR-19).
3. **SPEC §32/§111 false assumption.** "GitHub mirror" as black-start material assumes GitHub-hosted *artifacts* (GHCR, release assets, Pages chart repos) are also available. A GitHub platform outage makes black start impossible without an artifact cache (DR-14).
4. **SPEC §29/§111 + §113.** The object-storage provider is a single failure domain for backups, tofu state, the journal and the S3 bundle copy (SI-28 covers only the combined loss). Stage 0 must add a procedure "replace object-storage provider" (DR-13) and, per SPEC §113's "add procedures discovered to be missing", "lost operator machine" (DR-29).
5. **ADR-0019 vs SPEC §113 (CNPG PITR, Authentik restore).** Disabling admin merge override forces a non-PR recovery path for databases whose loss disables the merge gate. Record the direct-apply-plus-follow-up-PR exception as the accepted interpretation (DR-3).
